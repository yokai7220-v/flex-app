# Гибкость — PWA по годовому плану Меррика

Vite + React + TS + vite-plugin-pwa. Данные только в IndexedDB на устройстве (без сервера). Деплой — GitHub Pages через `.github/workflows/deploy.yml` на push в `main`, адрес `https://yokai7220-v.github.io/flex-app/`.

## Команды

- `npm run dev` — дев-сервер (`/flex-app/`)
- `npm run build` — проверка типов + сборка; это основная проверка перед коммитом
- `npm run check-videos` — проверить, что все YouTube-ID из `src/data/program.ts` живы
- Скриншоты состояний: дев-сервер на 5199, затем Playwright MCP `browser_run_code_unsafe` с `filename: scripts/verify/shots.js` → `/tmp/flex-verify`

## Правила

- Весь контент (уровни, рутины, видео, тексты) — только в `src/data/program.ts`; экраны контент не хардкодят.
- Не класть артефакты проверки внутрь проекта под .gitignore — агент не может их прочитать; писать в `/tmp`.
- Не восстанавливать вложенный маршрут при старте (`nav.tsx` открывает корень вкладки), иначе «Назад» после перезагрузки ведёт в никуда.
- Не вызывать `navigator.share` после долгой асинхронной работы — iOS теряет «жест пользователя»; бэкап собирается первой кнопкой, отдаётся второй.
- Не включать текущую неделю в скользящее среднее графика — неполная неделя тянет линию вниз.
- Новые зависимости — только версии, опубликованные больше 7 дней назад, с `--save-exact`.
- Уровни называть по лестнице Меррика (Basic, Basic+, Intermediate, Advanced) — свои имена не выдумывать.
- «Замер» — третья пилюля во вкладке «Прогресс»: она не подвид, а переход в `RoutineDetail` для `testRoutine`. Пилюле-навигации нужен `Seg<string>` — `route.sub` типизирован `'stats' | 'photos'`.
- Перед браузерной проверкой новой сборки снимать регистрацию service worker и чистить `caches` — `vite preview` отдаёт закэшированный старый билд.
- Тексты писать сухими: без оправданий, эпитетов и обнадёживающих хвостов — лишнее вычищено раз, повторять не надо.
